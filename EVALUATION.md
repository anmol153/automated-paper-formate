# Evaluation report: engine vs. manual checking

Generated by `python -m app.evaluation.runner` (writes `evaluation_report.json`).

## What is being measured

Sixteen papers, each built to violate a known set of rules and each declaring
that set as ground truth. Every fixture is pushed through `assess_paper()`, the
same function the API calls, so the evaluation cannot drift from production.

Three numbers are reported, kept separate on purpose:

- **flaw detection rate** — of the violations planted on purpose, how many did
  the engine report? This measures recall.
- **verdict agreement** — did the accept/reject outcome match what a manager
  would have decided by hand? This is the number that matters operationally,
  because a submission is rejected or not regardless of which rule fired.
- **over-reporting** — findings raised on fixtures with no planted cause. This
  measures precision. The `compliant-baseline` fixture is the control: it must
  produce nothing.

## Bugs the evaluation found and that are now fixed

### 1. Every correctly anonymised LaTeX paper was rejected (blocking false positive)

`anonymisation.author_block` fired on `\author{Anonymous Author}` — the literal
placeholder the double-blind instructions tell authors to use. This appeared on
11 of 16 fixtures, including a paper that was otherwise entirely compliant.

Cause: `fact_extractor._extract_identity` set `author_block_present = True`
whenever an `\author{}` block existed and was non-empty, without checking
whether the text was a placeholder. There was already an
`_ANON_PLACEHOLDER_RE` and an `anonymisation.placeholder` rule, but the
author-block check never consulted them.

Fix: a block is only treated as identifying if it carries a placeholder *and*
no name-like tokens. Added `author_block_placeholder_only` to
`IdentityFacts`/`StructureFacts` so the distinction is visible to the API, and
the check now reports "No author block (anonymous placeholder only)" so an
author can see the placeholder was recognised rather than ignored.

This was the single highest-impact defect found: it would have rejected most
correct submissions.

### 2. Unreadable line spacing silently downgraded every LaTeX verdict

A LaTeX source that does not declare `\linespread` yields `line_spacing = None`,
which the engine correctly reports as `missing`. But the verdict logic treated
`missing` as a finding, so a compliant paper came back `needs_review` rather
than `accepted`. The check is right; the fixture was incomplete. The compliant
baseline now declares `\linespread{1.0}` explicitly, and the distinction is
worth keeping in mind for real LaTeX sources.

## Known limitations (deliberate, and now pinned by a test)

### `anonymisation.metadata.title` and `anonymisation.metadata.producer` over-report

Both are in the default `forbidden_metadata_fields`, so a PDF with any document
title, or produced by "Microsoft Word 16.0", is reported as an anonymisation
leak. Neither identifies an author. `author`, `creator`, `subject` and `keywords`
are all legitimate targets, and those do carry identity in practice.

Not changed, because the fix is a venue-configuration decision rather than a
code bug: drop `title` and `producer` from `forbidden_metadata_fields` for venues
that do not want them. `test_known_over_reporting_is_limited_to_metadata_title_and_producer`
fails if this set grows, so new noise will not pass unnoticed.

### Unparseable files get no format-specific guidance

A `.doc` file is rejected at ingest before the extension rule is consulted, so
the author is told "not a recognised format" rather than the more actionable
"this template accepts pdf, tex, docx — please convert". The extension is known
from the filename even when the content cannot be read, so this is fixable, but
it needs a decision about whether the ingest short-circuit should still emit
file-level rules. Left as-is and recorded here.

### LaTeX and DOCX page counts are estimates

`page_count_exact` is `True` only for PDFs. For source formats the page count is
estimated from content volume, and `page.limit` enforces the venue limit against
that estimate. A paper near the boundary can therefore be judged wrongly in
either direction. Closing this requires rendering the source (a LaTeX toolchain
or a Word renderer), which is out of scope for the parser-only design.

### Verdict granularity comes from the rule set, not the engine

Severity is assigned per rule in the engine (typography, references and abstract
length are warnings; anonymisation and structure are blocking). A venue that
wants a wrong font to be fatal must set `decision.reject_if_any_warning = True`
rather than expecting a per-rule toggle. The evaluation runs with that flag on,
which is why the typography-only fixtures are `rejected`. With the default
(`False`) those same papers would be `needs_review`.

## Reproducing

```bash
cd backend && ../.venv/bin/python -m app.evaluation.runner
```

Exits non-zero if verdict agreement drops below 100% or the clean baseline
reports anything, so it can be wired into CI. The corpus invariants are also
asserted in `backend/tests/test_evaluation_corpus.py`.
